**Editing the visible message may leave a separate stored memory unchanged.** SpicyChat's [Semantic Memory 2.0 documentation](https://docs.spicychat.ai/product-guides/premium-features/semantic-memory-2.0) explicitly describes this separation. It explains one reason an obsolete detail can return after the transcript was corrected.

This guide concerns harmless fictional continuity. Do not use real personal secrets to test whether a system remembers them, and do not treat a generated answer as proof of the provider's data-retention behavior.

## A transcript is not the only context source

The service describes semantic memories as compact summaries used separately from full messages. A corrected sentence and an older summary can therefore conflict. The visible edit alone does not establish that every other source was changed.

Imagine a fictional train station originally named North Quay. You revise the story so it is East Quay, but a stored note still names North Quay. The old answer has a plausible source to inspect; it does not prove that the edit failed to save.

## Identify the exact contradiction

Write one short statement of the intended fictional fact. Compare it with the current message and any relevant memory entry available in your account.

| Layer | What to check |
| --- | --- |
| Visible transcript | Does the edited passage show the intended version? |
| Stored memory | Is an obsolete summary still present? |
| New response | Does the reply use the old fact, new fact or neither? |

Do not change several unrelated settings and facts at once. If the next answer changes, you would no longer know which intervention mattered.

## Review the separate memory control

The [Memory Manager guide](https://docs.spicychat.ai/product-guides/premium-features/memory-manager) describes adding, editing and deleting entries. Availability depends on the account and conversation. Use the controls actually present rather than assuming that every tier has an identical screen.

If you correct a note, keep it direct and internally consistent. In the fictional example, a note saying the station is East Quay is less ambiguous than a long paragraph containing both names without explaining the revision.

## Keep functional correction separate from deletion claims

The manager documentation says deleting a memory does not remove messages that already refer to it. Conversely, editing a message does not automatically update the stored memory. A tidy response later is evidence about that response, not a certificate that every copy of data was erased.

If the obsolete detail persists, record the minimal fictional example, relevant account feature and observed behavior for official support. Do not publish a private conversation to demonstrate it. The useful outcome is an understandable source of the contradiction and a correction limited to the information you intended to change.
